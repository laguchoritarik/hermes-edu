# Hermes Edu v0.1 implementation plan

## Assessment

At the start, the repository was an architecture scaffold: source modules contain docstrings, one import smoke test exists, `uv.lock` and a local virtual environment exist, and XeLaTeX is not installed in this environment. The first milestone is a mathematics TD vertical slice. No nested `AGENTS.md` applies.

## Architecture constraints

Dependencies point inward: adapters, interfaces and LangGraph orchestration → application ports/use cases → pure domain. Only `bootstrap.py` wires concrete adapters. Checkpoint state contains serializable values, not service clients. Retrieved facts retain provenance. Model output is validated. Revision, context, subprocess and path access are bounded.

## Test strategy

Pure contract and policy tests run offline. Adapter integration uses fake OpenAI clients, deterministic embeddings, temporary SQLite, fake compiler, and MCP in-process testing. The complete graph test uses synthetic educational text and a scripted model; XeLaTeX integration is conditional on the executable.

## External dependencies and blockers

XeLaTeX is absent; a genuine PDF compilation requires a TeX installation. The compiler's fixed arguments, timeout, missing-engine failure and source validation are tested offline. The configured DeepSeek credential enabled a successful live TeX-only run. Optional DeepInfra embeddings require their own credential. The dependency audit succeeded with package-index access.

## Risks and mitigations

- Synthetic curriculum must never be represented as official; label provenance explicitly.
- TeX generated from a model may contain dangerous commands; render text through a controlled template, validate source, restrict paths and disable shell escape.
- Model-produced mathematics may be wrong; structured audits and human approval reduce risk but do not establish formal correctness.
- Checkpoint format is security-sensitive; require strict msgpack before creating a database.
- Token prices change; label the dated provider estimate, allow overrides and mark unknown models.

## Decisions requiring ADRs

- v0.1 local embedding/retrieval strategy and index versioning.
- Structured draft and safe LaTeX rendering contract.
- Checkpoint and approval semantics for the TD workflow.
